JavaScriptでタブを動かす

第4章　JavaScriptでタブを動かす

4.1 知る：見た目を整えたタブに動作を加える

前章では、HTMLにCSSを適用し、タブや検索フォームの見た目を整えました。しかし、CSSは「どのタブが選ばれたか」をクリックから判断してくれるわけではありません。

本章では、JavaScriptを使って、利用者がタブを選ぶと対応する内容だけが表示されるようにします。完成した「New Tab」のうち、扱うのは「1 検索」と「2 ニュース」の切り替えです。すでにあるHTMLとCSSに、操作に応じた状態の変更を結び付けることが目標です。

4.2 知る：JavaScript、DOM、イベントの役割

HTMLは構造を記述するものでした。またCSSは見た目を指定するものでした。 これに対してJavaScriptは、利用者の操作などに応じて、ページの状態や動作を変えるために使います。

ブラウザは読み込んだHTMLを、JavaScriptから参照・変更できる要素の集まりとして扱います。この仕組みをDOM（Document Object Model）と呼びます。たとえば、HTMLに書かれた<button>は、JavaScriptから取得して属性を読み取ったり、値を変更したりできます。DOMは、HTMLを単なる文字列として探すのではなく、「このボタン」「このパネル」という単位で扱うための仕組みです。

また、クリックやキー入力のような出来事をイベントと呼びます。イベントが起きたときに呼び出す処理を登録する仕組みがイベントリスナーです。今回の基本的な流れは、次のとおりです。

  1. JavaScriptがHTML内のタブとパネルを見つけます。
  2. タブがクリックされたときに実行する処理を登録します。
  3. クリックが発生すると、JavaScriptが選択状態と表示状態を更新します。
  4. ブラウザは更新されたHTMLの状態とCSSに従って画面を表示します。

ここで重要なのは、JavaScriptがタブの色を直接塗り替えているわけではないという点です。JavaScriptは選択状態を表す属性を書き換え、CSSがその属性を条件に見た目を変えています。

4.3 読み解く：HTMLに用意されたタブとパネル

まず、JavaScriptを読む前に、操作の対象となるHTMLを確認します。index.htmlからタブとパネルの開始部分を抜き出すと、次のようになっています。

<nav class="tabs" role="tablist" aria-label="新しいタブのメニュー">
  <button id="tab-search" type="button" class="filetab"
    role="tab" aria-selected="true" aria-controls="panel-search" tabindex="0">1 検索</button>
  <button id="tab-news" type="button" class="filetab"
    role="tab" aria-selected="false" aria-controls="panel-news" tabindex="-1">2 ニュース</button>
</nav>

<section id="panel-search" class="panel" role="tabpanel" aria-labelledby="tab-search">...</section>
<section id="panel-news" class="panel" role="tabpanel"
  aria-labelledby="tab-news" hidden>...</section>

ここでは、二つのタブをrole="tablist"というまとまりに入れ、各ボタンにrole="tab"、対応する表示領域にrole="tabpanel"を指定しています。roleは、要素がインターフェースの中でどのような役割を持つかを、支援技術に伝えるための属性です。また、aria-で始まる属性は、要素の関係や状態を伝えるために用いられます。

1 検索tab-searchpanel-searchpanel-search
2 ニュースtab-newspanel-newspanel-news

aria-controls="panel-news"はニュースタブから対象パネルを指します。aria-labelledby="tab-news"はパネルの名前付けにタブを使う指定です。JavaScriptもこの対応を参照します。

最初のHTMLでは、検索タブにaria-selected="true"、ニュースタブにaria-selected="false"が付いています。ニュースパネルにはhiddenがあるため、ページを開いた直後は検索パネルが表示される構成です。まず、この状態を覚えておいてください。

4.4 読み解く：tabs.js全体で行っていること

今回のJavaScriptは、tabs.jsというファイルにまとまっています。HTMLの<head>には次の指定をしてください

<script src="tabs.js" defer></script>

srcは読み込むファイルを指定します。deferは、HTMLの解析が終わってからこのスクリプトを実行するようブラウザーへ伝えるための要素になります。これはすべてのタブの要素が読み込まれる前に動作を行わないようにするためです。

tabs.js全体の処理は、大きく四つに分けられます。

  1. 要素の取得：タブを集め、それぞれに対応するパネルを取得する。
  2. 切り替え処理の定義：activateTabという関数に、選択状態と表示状態の更新をまとめる。
  3. 操作の登録：クリックとAltキーを使った操作からactivateTabを呼び出す。
  4. 初期化：最後にactivateTab(0)を実行し、検索タブを選択状態にする。

ここでいう関数は、名前を付けてひとまとまりにした処理です。関数を呼び出すことで、同じ変更を複数の操作から実行できます。「要素を見つける→操作を待つ→状態を変える」というJavaScriptの流れを意識してください。

ここでconst、let、functionを確認します。 constは再代入できない変数、letは再代入できる変数、functionは処理をまとめる関数です。

4.5 読み解く：タブとパネルを取得する

最初に、tabs.js冒頭の2行を見ます。

const tabs = [...document.querySelectorAll('[role="tab"]')];
const panels = tabs.map(tab => document.getElementById(tab.getAttribute('aria-controls')));

documentは、現在のHTML文書をDOMとして扱うための入口です。querySelectorAll('[role="tab"]')は、CSSのセレクターと同じ書き方を使って、role="tab"を持つ要素をすべて取得します。今回は「1 検索」と「2 ニュース」の二つです。

querySelectorAllは要素の集まりであるNodeListを返します。[...]で配列に変えると、mapなどの処理を使えます。

mapで各タブに対応するパネルを探します。getAttribute('aria-controls')で"panel-news"を読み、getElementByIdへ渡します。

配列の対応は次のようになります。

配列の番号tabsに入る要素panelsに入る要素
0検索タブ（tab-search）検索パネル（panel-search）
1ニュースタブ（tab-news）ニュースパネル（panel-news）

tabs[1]とpanels[1]のように、同じ番号で対応するものを扱えることが、この後の処理の基礎になります。なお、指定したidを持つ要素が見つからない場合、getElementByIdはnull（該当する要素がないことを示す値）を返します。HTMLの名前が一致しているかどうかは、単なる見た目の問題ではなく、JavaScriptの動作に関わります。

ここでJavaScriptにおいて混同しやすいNullとUndefined について軽くさらっておきます。 • undefined：値が「未定義」でまだ何も割り当てられていない • null：値が「空」であり意図的に空っぽにしているといった違いがあります。

4.6 読み解く：activateTabが三つの状態を更新する

次は、タブ切り替えを担当する関数です。

function activateTab(index, moveFocus = false) {
  if (index < 0 || index >= tabs.length || !panels[index]) return;
  tabs.forEach((tab, i) => {
    const selected = i === index;
    tab.setAttribute('aria-selected', String(selected));
    tab.tabIndex = selected ? 0 : -1;
    panels[i].hidden = !selected;
  });
  if (moveFocus) tabs[index].focus();
}

activateTab(0)は検索、activateTab(1)はニュースを選びます。冒頭のifは不正な番号やパネル欠落時にreturnで処理を止めます。

forEachで各タブを調べ、i === indexが一致するときのtrueをselectedに入れて状態を更新します。

コード何を変えるか画面や操作への影響
tab.setAttribute('aria-selected', String(selected))タブの選択状態を表す属性支援技術に選択状態を伝え、CSSの選択条件にも使われる
tab.tabIndex = selected ? 0 : -1Tabキーで順番に移動するときの対象選択中のタブだけを通常のTabキー移動の対象にする
panels[i].hidden = !selected対応するパネルの非表示状態選択されていないパネルを隠す

setAttributeで属性を変更し、String(selected)で真偽値を"true"／"false"の文字列にします。aria-selectedはCSSの選択中表示に使われます。

.filetab[aria-selected="true"] {
  background: var(--surface);
  border-color: var(--border);
  color: var(--text);
}

tabIndexの0は通常のTab移動の対象、-1は対象外です。-1でもJavaScriptからフォーカスできます。

!selectedは真偽値を反転します。選択中はhidden = falseで表示、それ以外はtrueで非表示にします。

たとえばactivateTab(1)を呼び出した直後の状態を整理すると、次のようになります。

要素aria-selectedtabIndexパネルのhidden
検索タブ／検索パネルfalse-1true（非表示）
ニュースタブ／ニュースパネルtrue0false（表示）

タブの選択状態・Tab移動・表示を同じ関数で更新します。moveFocusは既定でfalseのため、現状の呼び出しではfocus()による移動は起きません。

4.7 読み解く：クリックとAltキーを同じ関数につなぐ

切り替える規則ができたので、次は利用者の操作と結び付けます。クリックを受け取る部分は次のとおりです。

tabs.forEach((tab, index) => {
  tab.addEventListener('click', () => activateTab(index));
});

addEventListener('click', ...)でクリック時の処理を登録し、() => activateTab(index)で選んだタブの番号を渡します。

window.addEventListener('keydown', event => {
  if (!event.altKey || event.ctrlKey || event.shiftKey || event.metaKey) return;
  if (event.key === '1' || event.key === '2') {
    const index = Number(event.key) - 1;
    if (index < tabs.length) {
      event.preventDefault();
      activateTab(index);
    }
  }
});

keydownはキーを押したときのイベントです。eventから修飾キーと1／2を確認し、対象の操作だけを受け付けます。

Number(event.key) - 1は、キーの文字"1"または"2"を数値に変え、配列の番号0または1に合わせる処理です。event.preventDefault()は、ブラウザ側で行われる既定の動作を、そのイベントが取り消し可能な場合に抑えるための呼び出しです。

クリックでもAltキーでも、最後に呼び出すのは同じactivateTabです。「クリック用の切り替え」「キー操作用の切り替え」を別々に作らないことで、選択状態の更新が食い違う可能性を減らせます。なお、このイベントはwindowに登録されているため、ページ内の別の場所でキーを押しても条件が合えば処理されます。

4.8 考える：初期表示と、実装されている範囲

tabs.jsの最後には、次の一行があります。

activateTab(0);

HTMLだけを読み込んだ時点でも、検索タブにはaria-selected="true"、ニュースパネルにはhiddenが指定されています。JavaScriptが実行されると、activateTab(0)があらためて検索タブを選び、タブとパネルの状態をそろえます。初期表示を明示しておくと、クリックを待つ前に、どちらが選択中かをコードから読み取れます。

JavaScriptを無効にするとタブは切り替わりませんが、検索フォームのGET送信はHTMLのactionとmethodで動きます。

4.9 試す：ブラウザと開発者ツールで状態を確かめる

index.html、style.css、tabs.jsを同じフォルダーに置き、index.htmlをブラウザで開きます。検索タブと検索欄が見えることを確認したら「2 ニュース」をクリックし、ニュースパネルの「第6章でニュースを自動取得します。」と検索フォームが隠れる状態を確認します。「1 検索」をクリックすると元に戻ります。

コンソール（Console）では、JavaScriptの式を直接入力して値を確認できます。

document.getElementById('tab-news').getAttribute('aria-selected')
// 期待する結果: "true"

document.getElementById('panel-news').hidden
// 期待する結果: false

"true"は属性から取得した文字列で、falseはプロパティの真偽値です。同じ状態を調べていても、取り出した値の種類が違うことに注目してください。

4.10 試す：一か所だけ変更して結果を予測する

ここからは、小さな変更を加えて検証します。

実験1：最初に表示するタブを変える

  1. 変更前にページを開き、検索パネルが最初に表示されることを確認します。
  2. activateTab(0)をactivateTab(1)にすると、何が表示されるか予測して記録します。
  3. tabs.jsの最後の一行だけを次のように変更します。
   activateTab(1);
  1. 保存してページを再読み込みし、最初からニュースパネルが表示されること、タブの選択状態もニュースに変わることを確認します。
  2. HTMLでは検索タブが選択された状態で書かれているのに、なぜニュースが表示されるのか説明します。手掛かりは、deferによる実行の順序とactivateTabの働きです。
  3. 最後にactivateTab(0)へ戻し、検索パネルから始まることを再確認します。

この実験から、HTMLの初期値とJavaScriptによって更新された状態を区別できます。どちらが実際の画面を決めているかを、再読み込み後に確かめるのがポイントです。

実験2：HTMLの対応関係を一時的に崩す

  1. 変更前にニュースタブで切り替えられることを確認します。
  2. aria-controlsに存在しないidを書いた場合、どこで問題が起きるか予測します。
  3. index.htmlのニュースタブの属性一か所だけを、aria-controls="panel-news-test"に変更します。ニュースパネル側のidは変えません。
  4. 保存して再読み込みし、画面の状態と開発者ツールのConsoleを確認します。今回のコードでは、panels[1]がnullになり、初期化の途中で存在しないパネルのhiddenを操作しようとしてエラーが起きることがあります。実際のエラーメッセージも記録しましょう。
  5. なぜタブとパネルの名前の不一致がJavaScriptのエラーにつながるのか、getElementById、map、panels[i].hiddenを手掛かりに説明します。
  6. 属性を必ずaria-controls="panel-news"に戻し、再読み込みしてクリック操作が復旧したことを確認します。

対応するパネルを一つ欠けさせると、activateTabのループ中にエラーが起こり得ます。現在の存在確認には改善の余地があります。

4.11 考える：フォーカスと操作方法をどう設計するか

moveFocus = falseは引数省略時の既定値です。現状のクリック・Altキー操作では、表示は切り替わりますがフォーカスは移動しません。

発展的な確認として、Altキーの処理にあるactivateTab(index);だけを一時的にactivateTab(index, true);へ変えると、切り替え先のタブへfocus()が呼び出されます。変更前後でConsoleにdocument.activeElement.idと入力し、現在のフォーカス先を比べてみましょう。変更する前に結果を予測し、確認後は元に戻してください。

aria-selectedは選択状態、tabIndexはTab移動の対象、focus()はフォーカス移動を扱います。三つの役割を区別しましょう。

4.13 ふりかえり：構造・状態・見た目をつなげる

本章では、DOMを通じてタブとパネルを取得し、イベントリスナーからactivateTabを呼び出して表示を切り替える仕組みを読み解きました。aria-controlsとidはHTML上の対応関係を示し、JavaScriptはaria-selected、tabIndex、hiddenを更新します。そして、CSSが選択されたタブの見た目を決めます。

大切なのは、画面上の動作を観察し、対応するHTML・CSS・JavaScriptを探して、変更の結果を予測し、実際の状態を確認するという学び方です。この方法を使えば、自分で書いたコードだけでなく、他人や生成AIが作ったコードについても、動作の根拠をもって制作に生かすことができます。
