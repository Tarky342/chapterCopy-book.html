# V-06-001｜APIキーをブラウザに出さないニュース取得の経路

## 読者の疑問と到達点

- 読者の疑問: 「ニュースは、どうしてブラウザの画面に表示されるの？」
- つまずき: ブラウザ、Node.jsサーバー、GNews APIの役割とAPIキーの境界をコードだけで追いにくい。
- 図を見た後: ブラウザは自分のサーバーを呼び、APIキーを使う通信はサーバー内で行われると説明できる。

## 制作の目的

第6章の中心である「ブラウザから外部APIへ直接キーを送らない」構成を、3者の位置関係と一方向の境界で理解できるようにする。APIの内部仕様ではなく、ブラウザ側とサーバー側のコードを対応づけられることを目的とする。

- 前後で何を学ぶか: 図で3者の境界を確認してから、`app.js` の `fetch` と `server.mjs` の環境変数・ヘッダー処理を照合する。

## 制作依頼文（そのまま渡せる形）

白または透明背景の横長SVGを作成してください。左に「ブラウザ」、中央に境界線で囲った「Node.jsサーバー」、右に「GNews API」の3領域を置きます。ブラウザからサーバーへは `GET /api/news?keyword=...` の矢印、サーバーからGNews APIへはニュース取得の矢印、応答は逆向きの矢印で示してください。サーバー領域の内側に `GNEWS_API_KEY` と鍵の記号を置き、サーバーからGNews APIへ向かう矢印の近くに `X-Api-Key` と表示します。ブラウザ領域には「APIキーを持たない」と明記してください。画面へ戻る応答は「articles」とだけ示し、実在ニュース本文や画像は描かないでください。

## 必須の要素・ラベル

- ブラウザ、Node.jsサーバー、GNews APIの3領域。
- `GET /api/news?keyword=...`、`GNEWS_API_KEY`、`X-Api-Key`。
- APIキーがサーバー内に留まる境界。
- サーバーからブラウザへ戻る記事データの応答。

## 描かないこと・誤解防止

- ブラウザからGNews APIへ直接矢印を引かない。
- 実際のAPIキー、ニュース本文、第三者のロゴ、実在記事の画像は描かない。
- APIキーがブラウザへ返るような矢印や、暗号化を保証する説明を入れない。
- GNewsの件数、速度、可用性を保証する数字やバッジを入れない。
- 実装に基づく模式図であり、GNewsの実データを示す図ではないことを記載する。

## キャプション・代替テキスト

- キャプション: ブラウザはローカルサーバーの `/api/news` だけを呼び、サーバーがAPIキーを使ってGNews APIへ接続する。
- 代替テキスト: ブラウザからNode.jsサーバーを経由してGNews APIへニュースを取りに行き、APIキーはサーバー内だけで使われる経路を示す図。

## 根拠・検証方法

- `chapters/new-tab-8chapters/06-news/app.js` の `fetch('/api/news?keyword=' + encodeURIComponent('テクノロジー'))` をブラウザ側の送信先の根拠にする。
- `chapters/new-tab-8chapters/06-news/server.mjs` の `const apiKey = process.env.GNEWS_API_KEY?.trim();` をキーの保管場所の根拠にする。
- `chapters/new-tab-8chapters/06-news/server.mjs` の `headers: { 'X-Api-Key': apiKey }` をGNewsへの認証ヘッダーの根拠にする。
- 完成後、コードと図のラベルを照合し、NetworkでブラウザのリクエストURLにAPIキーが含まれないことを確認する。実キーは図に記録しない。

## 見た後の小さな行動

`app.js` の `fetch` の送信先、`server.mjs` の `GNEWS_API_KEY`、`X-Api-Key` の3箇所を順に探し、図の矢印と対応づける。
