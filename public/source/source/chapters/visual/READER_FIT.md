# 読者適合性と図の粒度 — 判断基準 v2

## 読者の出発点

- デザイン学科を中心とする大学生。画面やレイアウトには関心があるが、プログラミングは初学者。
- HTML/CSS/JavaScriptの役割と連携がまだ曖昧。コードの細部だけでは完成画面を想像しにくい。
- AIのコードをそのまま使うだけでなく、**画面と実コードを対応づけ、自分で変更・検証できる**ようになることが到達点。

**原則: 先に見たことのある画面、次にコード、最後に内部の仕組み。** 図の粒度は技術の難しさではなく、**その時点の読者が答えたい問い**で決める。

## 図の粒度（小さい順ではなく、学習の順序）

| `granularity` | 読者の問い | 主な素材 | 適した表現 | 避けること |
| --- | --- | --- | --- | --- |
| `overview` | 「何を作る？」「どこを見る？」 | 実画面・ワイヤーフレーム | 画面全体と1〜3か所の強調 | 技術の内部構造や多数のラベル |
| `correspondence` | 「この画面の部分はどのコード？」 | 実画面＋短い実コード | 1つの部品と1つの記述を線で結ぶ | コード全文・DOMツリー全体 |
| `one-step` | 「操作すると何が変わる？」 | 実画面の操作前後・短い矢印 | 入力→変化など、1つの因果関係 | 同時に多数の処理を追わせる |
| `detail`（例外） | 「なぜ内部でそうなる？」 | 構造図・複数段の処理図 | 前提知識が導入済みの箇所に限定 | 初回バッチでの発注・根拠なき深掘り |

`detail` は禁止ではないが、読者が先の3段階を理解してもなお必要な場合だけにする。`detail_reason` に理由を残し、初回の試作には採用しない。

## 一枚の図に載せる情報の予算

- **問いは1つ**。読者が見るべき中心を1つにする。
- **焦点要素は1〜4個**。例：画面の見出し、対応するHTML、対応を示す線。
- **ラベルは最大4個**。図の見出しやキャプションで説明できる文は画像に詰め込まない。
- **新出の専門語は最大1個**。未導入の専門語を列挙しない。
- **短い実コード**を使う場合は、関係する箇所のみを見せる。原則1〜3行を目安とし、長い場合は図の役割を再検討する。
- **省くものを先に決める**。CSSの詳細、サーバー内部、無関係な画面部品など、今回理解する必要がない情報は省略する。

この数値は静的検査で守れる上限であり、図を常に4要素にする指示ではない。実際は**最小限**がよい。

## 図が本当に必要か — 5つの問い

1. 読者が止まりそうな具体的な箇所はどこか？
2. 文章やコードだけでは追いにくい**位置・対応・変化**があるか？
3. 図を見た後、読者が説明できることは何か？
4. 読者は実コードや実画面で、何を一つ確かめられるか？
5. 図を省略しても学習目標を達成できるなら、依頼しないほうがよいか？

この5つに答えられない候補は `candidate_visual` に留めるか `no_visual_needed` にする。

## 章ごとの観察の入口（例示であり発注確定ではない）

| 章 | まず検討する視覚表現 | やりすぎの例 |
| --- | --- | --- |
| 00 はじめに | 目指すNew Tab画面と作る要素の位置 | 全技術のシステム構成図 |
| 01 設計 | ワイヤーフレームと役割の対応 | UI設計理論を網羅した分類図 |
| 02 HTML | 画面の見出しと該当HTMLの対応 | DOM階層の全展開 |
| 03 CSS | 同じHTMLのスタイル適用前後 | CSSの全プロパティ体系 |
| 04 タブ | クリック前→クリック後 | イベント伝播の詳細図 |
| 05 検索 | 入力→検索結果へ進む流れ | URLやブラウザの内部仕様を網羅 |
| 06 ニュース | 画面にニュースが届く大まかな経路 | 未導入の通信・認証詳細を一枚に集約 |
| 07 デバッグ | 予想した結果→実際の結果→確認 | 開発者ツール全機能の一覧 |
| 08 完成 | 小さく変更→確認→改善の循環 | 開発プロセス全体の細かな工程表 |
| 99 まとめ | できるようになったことの振り返り | 全章を一枚に詰め込んだ情報図 |

**注意:** この表は仮説。実際の本文・実装を読んだ結果、図が不要なら発注しない。特に06の内部経路はコードを確認するまで描かない。

## 良い依頼と悪い依頼（説明用の仮例）

**悪い例:** 「HTMLの構造を正確に示すため、タグ、属性、DOM、CSSセレクタ、イベントとの関係を一枚の図にする」。内容が正確でも、この章の読者には一度に多すぎる。

**良い例:** 「画面の見出しを一か所だけ囲み、横にその見出しを表すHTMLの短い記述を置いて線で結ぶ。読者が『このコードがこの表示を作る』と説明できるようにする。CSSとJavaScriptの説明は入れない」。

これらは教材の実コードを確認した例ではない。実際の依頼は必ず該当章のファイルで根拠を確認する。

## 人間による確認

- **5秒テスト:** 初学者が注目すべき場所を指せるか。
- **30秒テスト:** 図の関係を自分の言葉で一文にできるか。
- **行動テスト:** 図を見た後、該当するコードや画面の箇所を探せるか。
- **省略テスト:** 要素を一つ減らしても伝わるなら減らす。

これらは静的チェックでは保証できない。ユーザーや初学者の目で確認する。
